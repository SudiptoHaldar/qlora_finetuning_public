## What was implemented

- **`qlora_finetuning/__init__.py`**: `__version__` read from `release_number.md`, with
  `0+unknown` when the file is absent or empty. Imports nothing else from the package.
- **`qlora_finetuning/settings.py`**: `get_str` and `get_int` look in the environment, then in
  `.env`, and raise `ConfigError` naming the variable. `.env` values are never written to the
  process environment. `load_config(name, required, config_dir)` reads `config/<name>.yaml`,
  requires an integer `version`, lists every missing required key, and returns a new dict each
  call.
- **`qlora_finetuning/logging_setup.py`**: `setup_logging()` adds one handler on standard
  error and sets the level from its argument, `LOG_LEVEL`, or INFO; `get_logger(name)`.
- **Eight sub-packages**, each an `__init__.py` with a one-line description.
- **`scripts/aws_check.py`**: its own YAML loading and `ConfigError` are gone; it calls
  `load_config()`. Checks, output, and exit codes are unchanged.
- **`pytest.ini`**: `network`, `gpu`, `paid` registered and deselected; unknown markers are an
  error.
- **`ruff.toml`**: line length 100, target `py310`, rule sets E, W, F, I, UP, B.
- **`.github/workflows/ci.yml`**: pull requests to `main` and pushes to `main`; Ubuntu, Python
  3.13; install, lint, test; read-only permissions; no secrets.

## Differences from the spec

- **By-path hint.** The spec said a script started by file path would fail with
  `ModuleNotFoundError`. It now prints "Run this script as a module from the repository root"
  and exits non-zero, with no traceback.
- **`--strict-markers`** added to `pytest.ini`, so a misspelt marker fails instead of silently
  running.
- **`ruff format`** was run on the four Python files with over-long lines, which also
  normalised some wrapping elsewhere in those files. CI does not check formatting.
- **`--config` must name a `.yaml` file**; another extension gives `CONFIG ERROR`.
