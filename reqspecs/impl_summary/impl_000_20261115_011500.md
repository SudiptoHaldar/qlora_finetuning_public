## What was implemented

- **Run registry.** `start_run(kind, label, path=..., arm=..., where=..., scope=..., configs=...)`
  checks every value, copies and hashes the named config files, writes `manifest.json` under
  `artifacts/runs/<run_id>/`, and appends a line to the runs index. `Run` is a context manager:
  leaving the block finishes the run as `completed`, an exception as `failed`. `list_runs` and
  `load_manifest` read back.
- **Cost ledger.** `LedgerRecord` carries seconds, instance type and count, token counts,
  number of questions, and a source (`measured`, `aws_api`, `computed`, `bill`). `Ledger`
  validates before writing, reads, drops replaced records, and totals per group, with
  billable instance-seconds computed as seconds times instances and dollar amounts added as
  decimals.
- **AWS mappers.** `record_from_sagemaker_job` and `record_from_converse_usage` build a record
  from a response dict. No AWS call is made anywhere in the package.
- **Guards.** A `measured` run refuses uncommitted changes or an unknown commit unless
  overridden, and the override is recorded. Labels, outputs, and records are checked for
  access key ids and email addresses.
- **`scripts/ledger_summary.py`.** Runs, totals per group, and the number of estimates;
  `--by` and `--json`.

## Differences from the spec

- **The clean-tree check ignores the `ledger/` folder.** Appending to the committed ledger
  changes the working tree, so without this a second measured run could never start before a
  commit. This refines spec D7.
- **A measured run also refuses an unknown commit**, not only uncommitted changes.
- **`allowed.paths`** (A, B, none) was added to `config/tracking.yaml` beside the values the
  spec listed.
- **`sum_converse_usage`** was added as a helper for adding up usage blocks.
- **The two ledger files are not created by this version**, as the spec said: `ledger/` holds
  only its README until the first real run.
