## What was implemented

- **Config.** `config/token_budget.yaml` pins the tokenizer (`Qwen/Qwen3-4B` at one commit,
  with a fingerprint of its vocabulary, chat template, and end token) and holds the two limits
  the training paths read: `max_length: 2048` and `max_new_tokens: 192`.
- **Counter.** `count_split(records, tokenizer, suffix)` counts each record's system text,
  user text, target with end token, and chat-templated prompt, in batches. The full sequence
  is prompt plus target. `load_tokenizer` imports `transformers` inside the function and reads
  the local cache; nothing but tokenizer files is loaded.
- **Report.** Per split: lengths at the 50th, 90th, 98th, 99th percentile and the extremes,
  records over each threshold, the ten longest by id, the token volume of one pass and the
  system text's share of it. Six checks. No example text, no prices, no timestamp.
- **Script.** `python -m scripts.finqa_tokens`, with `--check` and `--download`.

## Differences from the spec and the PRP

- **T3 checks a fingerprint, not the commit.** A loaded tokenizer does not reliably say which
  commit it came from, so the config pins a hash of its vocabulary, chat template, and end
  token, which proves the same thing more directly.
- **The thinking-off suffix is a config value**, so the check is not tied to Qwen in code.
- **Percentiles are nearest rank**, including the 50th, so every figure is a whole number.

## What it changed in the plan

- Training length 2,048 tokens instead of 1,536; reply limit 192 confirmed.
- Hosted training volume 9.76M tokens for three epochs instead of 14.6M. The execution plan's
  cost table now gives Nova Pro fine-tuning about $78, Nova Lite about $20, and Path B about
  $102 in total, down from about $155. These count tokens with the Qwen tokenizer as a
  stand-in for Nova's.
