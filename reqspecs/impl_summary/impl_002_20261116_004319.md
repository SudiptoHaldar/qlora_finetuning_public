## What was implemented

- **Comparison rule.** `numbers_match`: two numbers match when they differ by at most the
  larger of an absolute allowance and a relative one times the gold value. `values_match`
  adds `yes` / `no`, which match exactly and never match a number. The allowances are in
  `config/evaluation.yaml`: absolute 0.00001 and relative 0.5%, for the executed value and
  for the answer line.
- **Answer reader.** `read_answer` reads the text after `ANSWER:` as `yes` / `no` or a number
  that may carry a `$`, thousands separators, a sign, and an exponent. An answer ending in
  `%` gives two readings, the number and the number divided by 100. Characters are checked
  by hand before conversion; words, brackets, and two numbers are not an answer.
- **Gold reply.** `Gold.from_target` reads a canonical record's target: the parsed program
  and the gold value from the answer line.
- **Program match.** `programs_match` compares steps in order, numbers by value (`4850.0`
  and `4850`, `const_100` and `100`, `6.9%` and `0.069`), references by step, row names by
  text; a table step's second argument is ignored. Argument order and step order matter.
- **Scoring.** `score_reply` gives an `ExampleScore`: the four true-or-false results, whether
  the program executed, the error code, the deviations, a mismatch label (`scale`, `sign`,
  `kind`, `other`), and the relative gap. `summarize` gives counts and rates over all
  examples and over the unflagged ones.
- **Gold self-check.** `data/gold_check.py` builds each example's gold reply with the
  serializer, runs it, and scores it against itself. It builds the report with checks K1 to
  K7 and the flags file, and `load_gold_flags()` reads the flagged ids for `summarize`.
- **Script.** `python -m scripts.finqa_gold_check` and `--check`; exit codes 0, 1, 2.

## Differences from the spec and the PRP

- **Execution accuracy uses relative 0.5%**, by the owner's decision. Spec D3, section 4.1,
  and section 7 were rewritten; the measured cost (8.65% of fit and dev examples have a wrong
  operand that still scores as right, against 0.87%) is recorded there and in the gotchas.
- **K5's wording no longer depends on whether a flags file existed before.** The half-built
  code said "no flags file before" on a first run and "as in the flags file" afterwards, so
  a second run would have rewritten the report and `--check` would have called it out of
  date. Found while writing the script tests; fixed before the first real run.
- **K6 is "the manifest describes this data"**, and **a gold reply that is not strict or not
  canonical fails K2 without being a flag**. Both were announced by the PRP and are now
  written into spec section 4.3. `unserializable` is a fourth reason for a flag.
- **The share of the allowance is printed with its digits** in the Markdown report; the
  shared number formatter would have shown one decimal place.
- **Largest gap**: the acceptance line said "half the allowance". Under the decided rule it
  is 0.494; under the tight rule it is exactly 0.5. The line now says "at most half".
