## What was implemented

- **`Predictor` protocol.** `predict(requests) -> predictions`: a list in, a list of the same
  length out. A request holds the canonical record's system and user texts and the reply
  limit; a prediction holds the reply text, token counts (or unknown), latency, and a stop
  reason. `check_predictions` refuses anything malformed; `describe` gives the plain values
  that go into the run and the resume check.
- **Fake predictor.** Answers from a table or a function, counts a token per word, and can
  fail after N requests. `gold_predictor` gives each example its own gold reply.
- **Predictions file.** One JSON line per example, written and forced to disk after each
  batch. `read_predictions` accepts only a clean beginning of the split, drops a cut-off
  last line, and names the line of any other damage.
- **Runner.** `run_evaluation` predicts a split in dataset order inside one registry run,
  scores every reply, and records the run's usage in a `finally`, so a failed run records
  what it consumed. A predictor failure stops the run with the run id on the error.
- **Resuming.** A new run that copies the valid lines of an earlier one and continues. It is
  refused, before any run is created, unless the split, manifest, prompt, reply limit, and
  the predictor's name, model, and settings are the same.
- **Summary.** `summarize_run` scores every stored outcome again under the current config,
  totals with `summarize` and the gold flags, adds the tight-rule figure, token totals,
  latency, stop reasons, and checks R1 to R5. A run that passes them and is not partial is a
  result and adds one line to `ledger/evaluations.jsonl`.
- **Script.** `python -m scripts.evaluate` with `--predictor`, `--split`, `--limit`,
  `--resume`, `--summary`; exit codes 0, 1, 2. A table maps a predictor's name to its factory,
  kind, path, and arm; later versions add their backends there.

## Differences from the spec and the PRP

- **R1 is "every example asked for"**, and a result is "checks pass and not partial". As
  first written, an asked-for partial run would have printed a failed check.
- **R4 is "the ledger covers the lines"**, not "equals". A prediction paid for and then lost
  with a cut-off line is paid for again, and the ledger truthfully holds both.
- **A killed run's usage is rebuilt on resume.** A killed process writes no ledger record;
  the resuming run appends one for it from its lines, marked `computed`.
- **A line that `run_reply` could not have written** fails R5 and counts as wrong on
  everything. Found by a test: the first version of the summary crashed on such a line.
- **Token counts reach the ledger only when the predictor names a model** and every count is
  known, which is the ledger's own rule.
- **The batch size is not part of the resume check.** A backend whose replies depend on it
  puts it in `settings`.
- **The script catches `TestLockedError` to print it** and exit 2. The runner never catches
  it, and nothing is read or run; this is reporting, not a way round the lock.

All but the last two are written back into the spec (sections 4.4 and 11).
