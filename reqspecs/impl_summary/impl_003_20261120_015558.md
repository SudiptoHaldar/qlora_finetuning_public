## Summary

- **The `score` task** (`local_qlora/job.py`). One job scores the untuned model and then
  every checkpoint of a training run on dev, each as an ordinary evaluation run. Before
  each, `local_qlora/scoring.py` looks in the run registry for a run that asked the same
  model the same question: a complete one is reused, one that was cut short is resumed.
  Checkpoints are found along the whole chain of a resumed training.
- **The estimate** (`local_qlora/estimate.py`). The plan of a `train`, `score`, or
  `evaluate` job prints hours and dollars, computed from the seconds that the newest
  pulled job measured on the same instance type, and a proposed `--max-runtime`. Check J9
  fails when nothing has been measured or the estimate does not fit in the limit. The
  smoke job is exempt.
- **The selection** (`local_qlora/selection.py`, `scripts/qlora_select.py`). Recomputes
  every count from the pulled predictions files, runs six checks (every checkpoint scored
  once; same question; the right weights; the run it claims; measured in the cloud; scores
  current), and takes the best execution accuracy on dev; a tie goes to format validity,
  then to the earlier step. The loss is shown and never chooses. It writes
  `reports/local_qlora/adapter_selection.json` and `.md` only when all six pass: counts,
  ids, hashes, and amounts, with no time stamp, so the same runs give the same files. The
  verdict is `met` or `missed` against 40% execution accuracy and 98% format validity.
- **After the selection.** `--adapter selected` names the record's checkpoint in
  `scripts.evaluate` and in the launcher, and is refused if the weights here are not the
  ones that were scored. `sagemaker_job pull --checkpoint N` downloads one adapter.
  `sagemaker_job keep --yes` (the owner's) copies it and the record to `adapters/` in the
  bucket.

## Issues resolved

- **A smoke run could have been selected.** The first rehearsal showed that a local smoke
  run passed every check but L5. A smoke run is now refused outright unless `--check` is
  given, so that no change to L5 could ever let one become arm A1.
- **An earlier untuned baseline counted as a second result.** Runs of the untuned model at
  another batch size made L1 see more than one. Only the untuned run with the same
  settings as the checkpoints is counted.
- **Checkpoints are not on this machine after a pull**, so L3 could not hash them. It uses
  the hash the scoring job recorded in its result file, and the local file when it exists.
- **Adding J9 failed five existing launcher tests**, as it should have: a `train` plan
  with nothing measured must not pass. The tests were updated to say so.
- **A job on a fresh workspace has no checkpoints.** `score`, a resumed `train`, and a
  tuned `evaluate` are refused at `plan` without `--workspace`.
