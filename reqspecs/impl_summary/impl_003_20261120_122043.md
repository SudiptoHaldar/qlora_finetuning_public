## Summary

- **Preflight** (`local_qlora/local_run.py`). Six checks before a start, none of which
  starts anything: the plan and an estimate from the last local run's measured speed; a
  clean working tree; free GPU memory, with the programs that hold memory named; disk;
  AC power and no sleep; and that no training run is in progress or waiting to be resumed.
  The GPU is read through `nvidia-smi`, power through the Windows power status and
  `powercfg`; a probe that cannot read answers "unknown" and the check is skipped.
- **Progress line** (`run_status`). The step, the share done, seconds per step, hours left,
  the last loss and the last loss on dev, the checkpoints, and for a run that stopped, the
  command that continues it. Without a run id it takes the newest full run made here.
- **Local note** (`local_qlora/local_note.py`). The committed record of the run: hours,
  speed, peak GPU memory, the per-checkpoint table on quick-dev, the checkpoint the
  selection rule picks there, that checkpoint's result on all of dev, and the categories
  of its failures. Five checks must pass first. With a cloud selection present it adds the
  two side by side on dev, with no dollars. It is a file of its own, labelled "local run:
  not an arm of the comparison"; the selection record is never written or read for it.
- **One command** (`scripts/qlora_local.py`) for the three. Training, scoring, selection,
  and the settings were not changed.

## Issues resolved

- **The newest run was taken from the order of run ids**, and two runs that start in the
  same second sort by a random suffix. A resumed run could be reported as its own
  predecessor. The newest run is now the one no other run continues. A test found it.
- **A killed run is `started` in two places**, the index and its manifest; the first test
  helper changed only one. The code reads the manifest for a run's state and the index for
  "is anything running", and both agree for a real run.
- **"Running" needed a definition**: a run that was killed never gets a `finished` line.
  It is running while its files were written in the last 15 minutes.

## Notes for the owner

- **The preflight fails today, and that is the point of it.** 13.5 GiB of the card is free
  and 14.5 are asked; a resumed run reserved 13.6. Close the browser, the PDF reader, and
  the chat and phone apps before starting, or the run will spill into shared memory and
  take several times longer without failing. Lowering `local_run.min_free_gpu_gib` is
  possible and not recommended.
- **Changed after the build, by the owner: the threshold is 14.0 GiB.** With everything
  closed the card had 14.3 to 14.5 GiB free, because the Windows desktop holds 1.1 to 1.4,
  so 14.5 was on the edge. The figures above are as they were when this was built.
- **Your first SageMaker smoke job was in progress while I built this**, and a fix for it
  was in the working tree (`backend.py`, `job_bootstrap.sh`, a test). I did not touch those
  files or make any AWS call. Both went into release v1.16 together.
- **The GPU can do one thing at a time.** Do not start the local run while you want the
  laptop for anything else that uses it; the cloud jobs are unaffected by it.
- **The local selection is on quick-dev (200 examples), the cloud's on dev (499).** Only
  the two selected checkpoints on dev are comparable; the note says so.
- The code was committed by the owner as release v1.16 while the full test run was still
  going. The status documents (this file's figures, spec section 11, the roadmap, the
  execution plan, the PRP's status) were completed after that commit and are uncommitted.
