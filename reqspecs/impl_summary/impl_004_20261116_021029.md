## Summary

The evaluation runner can now ask Amazon Nova Pro and Amazon Nova Lite for replies.

- **Provider.** `FrontierProvider` has one method, `converse`. `BedrockProvider` implements
  it over the Converse API: the canonical system and user texts unchanged, the reply limit,
  temperature 0 and `topK` 1, nothing else. It reads the reply text, Bedrock's token counts,
  and the stop reason, and turns every failure into a `PredictorError` that holds the error
  code and no text. It is the only module that imports boto3.
- **Predictor.** `FrontierPredictor` gives the runner one prediction per request with
  `usage_source = "aws_api"`, so the runner's own ledger record carries Bedrock's counts.
  The factory checks the sign-in and the account with one free call before any run exists.
- **Scripts.** `scripts/evaluate.py` offers `nova-pro` (arm B0-Pro) and `nova-lite` (arm
  B0-Lite); an entry can now name its place (`bedrock`) and extra config files to snapshot.
  `scripts/aws_check.py` gains C8 (both models Active and callable on demand).
  `scripts/nova_baseline.py` turns four baseline runs into a committed report after checks
  B1 to B4.
- **Prices.** `config/pricing.yaml` holds the prices of the AWS price list published
  2026-11-11; `inference_cost` multiplies with `Decimal`.

## Issues resolved

- **botocore's `max_attempts` counts retries only.** The client uses `total_max_attempts`,
  so `max_attempts: 8` in the config means eight calls at most, as the comment there says.
- **A service error message can repeat request text.** It is logged and never put in the
  `PredictorError`, which is stored with the run. A test builds an error whose message
  holds the prompt and checks that none of it reaches the exception.
- **`aws_check` tests load the committed AWS config** and call the checks with it, so C8's
  model ids are added inside `load_aws_config` and not in `main`.
- **Seven lint findings** (six long lines, one unused import), fixed.
