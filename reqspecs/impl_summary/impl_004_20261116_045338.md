## Summary

`python -m scripts.nova_tune` has seven commands over one class, `BedrockTuning`.

- **`plan`** builds what a launch would send (names, the customization model id, the three
  S3 locations, the hyperparameters as text, the estimated tokens and cost) and runs nine
  checks. It starts nothing. A check that needs AWS and has no client is shown as skipped.
- **`launch`** runs the checks again and refuses unless all pass. It creates one job with
  a request token derived from the model, the files, the hyperparameters, and the attempt;
  a job that already exists with that token is adopted. The tuning record is written as soon
  as the ARN is known, then one ledger record with the estimated training tokens. The launch
  is a `train` run with scope `measured`.
- **`status`** reads the jobs and deployments, records how each ended and in which phase a
  failed one failed, and for a completed job downloads and summarizes the two loss-curve
  files. `--wait` repeats it every 60 seconds until nothing is pending.
- **`deploy`**, **`stop`**, **`bill`**, **`teardown`**: an on-demand deployment for a
  completed model; stopping a running job; the billed amount in place of the estimate;
  deleting a deployment and, with `--all`, the tuned model.

The owner's three decisions are built in: Bedrock's default learning rate and warmup steps
for both models; Nova Lite first; and check T9, which refuses a Nova Pro launch until Nova
Lite's job has completed and its billed amount has been entered.

## Issues resolved

- **A lost reply could have meant a second job.** A launch now looks for a job of the
  planned name first and adopts it if it carries this launch's token; a test loses the
  reply on purpose and ends with one job.
- **`status` with nothing launched asked for a sign-in.** It now says "no job has been
  launched" and exits 0 without one.
- **A test of mine reached AWS.** The module-form test ran `status`, which asks "who am
  I". It now runs `bill` for an unknown model, which asks nothing.
- **botocore printed a traceback for an expired sign-in**, through two loggers. Both are
  set to ERROR in `aws_session`; the operator sees one line with the command to run.
- **Five lint findings** (long lines, an import order), fixed.
