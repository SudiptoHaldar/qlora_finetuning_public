## Summary

**The freeze.** `python -m scripts.comparison_freeze freeze` writes down what each of the six
arms is: the name, model id, and settings of its predictor, taken from the arm's dev result
run, with the prompt id, the split manifest, the reply limit, and the hashes of the shared
config files and the gold flags. Eight checks must pass first. It reads committed records
and the dev runs on this machine; it calls no AWS service and loads no model.

**The unlock.** `comparison_freeze unlock --yes --freeze <hash>` is the owner's, once. The
owner types the beginning of the freeze record's SHA-256, which is the sign-off. The unlock
record names the freeze record and the commit that holds it. There is no way to lock again.

**The gate.** After the unlock the lock protects nothing, so `run_evaluation` itself puts
every run on `test` through `check_test_run`. A test run needs the frozen predictor and
shared files, scope `measured`, no `--limit`, the right place (a SageMaker job for a Qwen
arm, Bedrock for a Nova arm), and no earlier complete run for its arm. An unfinished run
must be resumed. The `gold` predictor may run on test as a free check.

**The two Qwen jobs.** `sagemaker_job bundle --split test` writes a bundle of the test
examples alone, only after the unlock. An `evaluate` job on test is given that bundle and
must pass a new launch check, J11, which asks the gate from this machine. `rehearse`
refuses the test split.

**The six-arm record.** `python -m scripts.comparison_runs record` checks the six runs
(C1 to C8) and writes `reports/comparison/six_arm_test_runs.json` and `.md`: run ids,
counts, tokens, billable seconds. No statistics, no dollars. `void` lets the owner discard a
run that a fault spoiled, with a written reason that the record shows as a deviation.

The owner started the PRP without changing the spec's six decisions, so they were taken as
recommended.

## Issues resolved

- **Config files have other bytes here than in a job.** Git checks them out with CRLF on
  this machine; `git archive` gives a job LF. A hash over raw bytes would have made the
  gate refuse every test job. Hashes are taken with Unix line ends (`file_sha256`). The PRP
  had this wrong: it read two equal hashes as proof that the bytes are equal.
- **The dev runs do not share config bytes.** The two Nova baselines hold other bytes of
  `evaluation.yaml` and `dsl.yaml` than the later runs. The freeze ties each dev run to
  today's files by rescoring it, not by comparing hashes.
- **A job's code has no `reports/` folder**, so the freeze record and the list of voided
  runs that the gate reads are under `splits/`.
- **`serialize_split("test")` would have opened with the unlock.** A real-data test relied
  on the lock to keep it closed. It now refuses whatever the lock says.
- **The local job runner writes a result file even for a refusal.** Trying
  `job_run evaluate --split test` here left `artifacts/jobs/local-evaluate/` (git-ignored);
  it was removed.
