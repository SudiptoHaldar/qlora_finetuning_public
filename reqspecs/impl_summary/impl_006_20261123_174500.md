## Summary

`venv\Scripts\python -m qlora_finetuning.demo` reads a question, a table, and optional
context from a JSON file, asks the Qwen model with the selected adapter on the local GPU,
and prints the proposed program, each step's value, the executed result, and whether the
model's own answer agrees with it. With no argument it answers one invented sample.

- **Nothing new for the model, the prompt, the reply, or the comparison.** The prompt is
  `load_prompt().system` and `format_user(...)`; the model is asked through the existing
  predictor with one request; the reply goes only to `run_reply`; the comparison is one
  new function in the metrics, `answer_agrees`, which no run summary reports.
- **`--check`** validates the inputs and finds the adapter without loading a model. For
  that, the checks of `build_tuned_predictor` became `resolve_tuned_adapter`; what either
  refuses or returns is unchanged, and the existing tests of Path A pass untouched.
- **The demo is not an evaluation.** No gold answer, no metric, no split name, no example
  id, no tracked run, no file written, no AWS call. Guard tests check the package's source
  for each of these.
- **The five decisions of spec section 8 were taken as recommended**, because the owner
  started the PRP and its execution without changing one.

## Issues resolved

- **The stand-in training run has other checkpoint steps than a smoke run.** The test
  helper now takes the first checkpoint that exists.
- **A guard read a guard.** `tests/data` scans every file for the raw reader's name; the
  demo's guard test builds that name from two pieces now.
- **A log handler bound to a closed stream** prints a logging error to standard error in
  tests that call `main` twice; the assertion looks for an output line, not for a word.
