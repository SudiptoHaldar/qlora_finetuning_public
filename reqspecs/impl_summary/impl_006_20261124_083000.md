## Summary

`venv\Scripts\python -m scripts.public_export build --to <folder>` writes a copy of a commit
that can be published as `SudiptoHaldar/qlora_finetuning_public`:

- **No history**, and none of the folders the owner left out.
- **The AWS account number is `123456789012`** in every file, the bucket and role names
  included. The private repository's name is the public one. A folder of the owner's
  machine, named in three documents, is a neutral one.
- **The runbook is `docs/runbook.md`**, and every mention of its old path is rewritten,
  in documents, in code, and in the tests that assert those messages.
- **`PUBLIC_SNAPSHOT.md`** says what the copy is and how it differs; the README and the
  runbook carry one line under their title that points to it.

`check --to <folder>` proves the copy: it is, byte for byte, what its commit exports;
no private string remains; lint and the whole suite pass in a scratch copy with the
training stack blocked; the only tests skipped for being public are the five that verify
the freeze records.

## Issues resolved

- **Two tests need a git repository.** They read "this repository's commit" and failed in a
  plain folder. The suite is now run in a scratch copy with one throwaway commit, as a
  checkout in CI has.
- **The email scan stalled** on a file of a million letters. It now looks only around each
  `@`, and a test holds a two-million-letter case.
- **A decorator was read as an email address**: `$` in the pattern matched before a line
  break. It is `\Z` now.
- **The notice named the runbook's old path**, which the scan rightly found. The notice
  gives the folder and the file name separately.
- **Tests plant private-looking values on purpose.** They are listed as invented in the
  config and set aside before a scan.
