## Why this group exists

This is the path both planning guides describe: a LoRA adapter trained on a 4-bit-quantized
`Qwen/Qwen3-4B`. The untuned model is measured first so the adapter's gain is demonstrated, not
assumed.

Decided 2026-11-14: the measured training and evaluation runs execute as SageMaker jobs on a
single 24 GB GPU instance, so Path A's cost is a billed dollar amount comparable with Path B's.
The local RTX 4090 Laptop GPU is used for development and smoke tests and produces no number in
the six-arm comparison. The same code, config, and pinned library versions run in both places.

Added 2026-11-14: the owner may also run the full fine-tune locally as a learning exercise
(v3.06). Its result is a side note comparing local and cloud time and dev accuracy; it has no
AWS bill, so it is kept out of the cost comparison.

Standing decisions (from the guides, plan §4.6): thinking disabled in the chat template; 4-bit
NF4 with double quantization; LoRA r=16, alpha=32, dropout 0.05 on all linear layers; batch 2 ×
accumulation 8; `paged_adamw_8bit`, LR 2e-4, cosine with 5% warmup; max sequence length 1,536;
gradient checkpointing; completion-only loss; checkpoint chosen by dev execution accuracy, not
loss; greedy decoding. The guides' values were sized for 16 GB and are kept for the first run
even though the cloud GPU has 24 GB. All values live in `config/`.
