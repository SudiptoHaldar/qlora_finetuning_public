## Why this group exists

The goal of the project is a cost and accuracy comparison of the two paths. Accuracy claims
are only credible if the 35% test split is read once, after both paths have frozen their
configurations. Cost claims are only credible if they come from logged measurements and stated
rates.

Standing decisions: six arms (A0 base Qwen, A1 QLoRA Qwen; B0 and B1 for each of Nova Pro and
Nova Lite) on identical prompts; paired statistics because every arm answers the same items;
every model costed in billed AWS dollars (SageMaker instance time for Qwen, Bedrock tokens and
storage for Nova); all rates in `config/` with the price-list date;
the report states the oracle-evidence setting and every deviation from the plan.

**To state in the report: who holds the tuned model** (noted 2026-11-21). This is a difference
between the paths that neither the accuracy table nor the cost table shows.

| | Path A: Qwen3-4B with QLoRA | Path B: Nova Pro and Nova Lite on Bedrock |
|---|---|---|
| What training produces | An adapter file the owner holds | A custom model inside Bedrock; the weights cannot be downloaded or exported |
| Where it can run | Anywhere: SageMaker, a local GPU, another cloud | Only through Bedrock, in the owner's AWS account |
| Can it be published | Yes, for example to Hugging Face, as an adapter or merged into the base model; check the Qwen3 licence (Apache 2.0) and the FinQA dataset's terms first | No |
| Cost of keeping it | Storage of a small file | $1.95 a month per model for as long as it exists |
| If it is deleted | Restore from any copy | Gone; the training job must be paid for again |
| If the provider changes price or retires the base model | No effect on the adapter | The tuned model is affected with it |

In short: Path A gives a portable model the owner owns; Path B gives a hosted model the
owner rents. The cost model of v5.02 should carry the storage line and the retraining cost
that this implies for Path B.
