## Summary

Every FinQA example is assigned to `fit`, `dev`, or `test`. Companies are kept whole: all
examples of one company are on one side, because annual reports repeat prior years' numbers
and a split by report would leak them. Order comes from SHA-256 of a fixed seed and the
company, not from a random generator, and a fill rule lands on 65.00% for training (5,383
examples: fit 4,884, dev 499) and 35.00% for test (2,898). Two hundred dev examples are
labelled quick-dev.

The assignments are committed in `splits/finqa_split_manifest.json` with a content hash and
are written once; the build command refuses to replace a different manifest. Code asks for
examples with `load_split(name)`. Asking for `test` raises until req_005 v5.01 creates an
unlock record naming the manifest hash, and a guard test restricts which files may use the raw
reader. A split report with counts per split, a leakage table, and ten checks is committed
under `reports/data/`.
